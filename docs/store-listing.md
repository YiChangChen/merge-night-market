## 7. 隱私揭露

依**上架時實際有的服務**填寫。目前只有 PostHog；AdMob（S1.4）與 Sentry（7.4）接上之後才加進來。三者都接上時的填法如下。

### App Store：App 隱私（營養標籤）

| 資料類型 | 來源 | 用途 | 與身分連結 | 用於追蹤 |
|---|---|---|---|---|
| 識別碼 → 裝置 ID | AdMob（廣告識別碼 IDFA，玩家允許追蹤時） | 第三方廣告 | 否 | **是** |
| 識別碼 → 裝置 ID | PostHog（App 自己產生的隨機匿名 ID） | 分析 | 否 | 否 |
| 使用資料 → 產品互動 | PostHog（遊戲事件） | 分析 | 否 | 否 |
| 使用資料 → 廣告資料 | AdMob | 第三方廣告 | 否 | **是** |
| 診斷 → 當機資料、效能資料、其他診斷資料 | Sentry；AdMob 也會收集 | App 功能、分析 | 否 | 否 |
| 位置 → 大略位置 | AdMob（由 IP 推算） | 第三方廣告 | 否 | **是** |

沒有收集：聯絡資訊、健康、財務、精確位置、通訊錄、使用者內容、瀏覽或搜尋紀錄、購買項目、敏感資訊。

如果最後決定只放非個人化廣告、不跳追蹤詢問（ATT），「用於追蹤」一欄全部改成「否」，也不需要 ATT 文案。

### App Tracking Transparency（ATT）文案

`NSUserTrackingUsageDescription`（在 `react-native-google-mobile-ads` 的 config plugin 設定 `userTrackingUsageDescription`）：

```
允許後，你看到的獎勵廣告會比較符合你的興趣。不允許也能照常看廣告領獎勵，遊戲內容完全不受影響。
```

文案要和實際行為一致：拒絕追蹤時仍然能看獎勵廣告（AdMob 會改播非個人化廣告），遊戲不會因此少任何東西。詢問的時間點建議放在**第一次要播廣告之前**，而不是一打開 App 就問。

### Google Play：資料安全性

| 資料類型 | 收集／分享 | 用途 | 是否必要 |
|---|---|---|---|
| 應用程式活動 → 應用程式互動 | 收集（PostHog） | 數據分析 | 可選（設定裡可關閉「分析資料」） |
| 裝置或其他 ID | 收集並分享（AdMob 廣告 ID；PostHog 匿名 ID） | 廣告或行銷、數據分析 | 廣告 ID：必要；匿名 ID：可選 |
| 應用程式資訊和效能 → 當機記錄、診斷資訊 | 收集（Sentry、AdMob） | 應用程式功能、數據分析 | 必要 |
| 位置 → 大概位置 | 收集並分享（AdMob） | 廣告或行銷 | 必要 |

- 資料在傳輸時加密：是（三個服務都走 HTTPS）。
- 使用者可以要求刪除資料：沒有帳號、資料不連結身分；說明「刪除 App 即重設匿名 ID，並可在設定關閉分析資料」。
- 「內含廣告」選「是」；目標年齡層 13 歲以上。

### 隱私權政策要同步改的地方

`docs/privacy-policy.md` 的「之後的版本」一節，要在接上 AdMob 與 Sentry 後改成實際內容，並和上面兩張表一致；生效日期、開發者名稱、聯絡信箱要填好。
