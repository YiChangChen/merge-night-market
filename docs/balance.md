# 夜市合成：平衡數值

數值的唯一來源是 `src/game/content/balance.ts`。這份文件放的是由規則層函式**算出來**的參考表，讓設計、教學（S6.4）與封測校正（S7.5）有共同的基準。

## 各玩家等級每單期望金幣

由 `expectedOrderCoins(playerLevel, stalls)` 算出（S1.6），是一般訂單金幣的數學期望值，對應 `createOrder` 的抽法：

- 鏈：從已開的攤位均勻抽（FR7）
- 階數：2 到 `min(2 + ⌊玩家等級 / 2⌋, 該鏈長度)` 均勻抽
- 品項數：玩家 Lv3 起有 40% 機率兩品項
- 金幣：每個品項 `5 × baseCost × 攤位加成`，攤位每升 1 級 +10%（FR8、FR15）

兩個欄位分別是：玩家完全沒有重開攤位（只有開局的手搖飲、炸物），以及依玩家等級把能重開的攤位都重開成 Lv1（麵線 Lv3、蒸籠 Lv5、甜品 Lv7）。攤位升到 Lv2／Lv3 後，金幣會再提高 10%／20%。

## 觀察（S1.6，2026-11-09）

- **新手存到 200 金幣比預期慢**：Lv1 每單期望 10 金幣、Lv2 為 15、Lv3 為 21。手搖飲或炸物升到 Lv2 要 200 金幣，照這個數字大約要 13–15 張訂單，S6.4 要求的「8 張訂單以內」達不到。這要在 S6.4 處理，例如調整新手訂單，或降低第一次升級的費用；這裡先記錄，不改數值。
- **重開攤位不會提高每單期望金幣**：兩個欄位一直到 Lv9 都一樣，因為金幣只看品項階數，和是哪一條鏈無關。Lv10 起各鏈長度不同，才會出現差距。重開攤位的經濟價值來自：之後的升級加成（每級 +10%）、人龍變長（完售獎勵，S2.1），以及發明菜（E3）。GDD 估計的「約 2 週走完」，要把這一點納入考量。
- 實測校正留到 S7.5 的封測。

## 新手訂單（S6.4，2026-11-11）

處理上面「新手存到 200 金幣比預期慢」的問題，讓教學第 3 步（升級攤位）一定能完成。

- **調整**：教學期間（`meta.tutorialStep < 3`）建立的一般單，金幣 ×`tutorialOrderCoinMultiplier`（2.5），在建立訂單時鎖定（RC-3）。教學完成後建立的訂單恢復原價。
- **驗證**（`src/game/__tests__/tutorial-test.ts`）：
  - Lv1 的訂單都是 L2，每張 25 金幣；前 7 張一定在 Lv1 建立（做完 5 張才升 Lv2，補單晚一張），第 8 張至少 25，所以 **8 張最少 200 金幣**。
  - 用 `expectedOrderCoins` 依累計 XP 推算 8 張訂單的期望總和 ≥ 200。
  - 50 個 seed 實際交 8 張單，每一局都 ≥ 200。
- 只在玩家 Lv2 以下套用（`tutorialBonusMaxLevel`，E6 code review）：前 8 張單一定在 Lv1、Lv2 建立，保證不變；玩家一直不升級攤位、教學沒完成時，到 Lv3 也會恢復原價，不能無限期拿 ×2.5。
- 貴客單與線索單不受影響（教學期間還沒有發明菜，不會出現）。
- 實測校正一樣留到 S7.5。

## 進度模擬（S7.5，2026-11-25）

封測前先用規則層模擬，當作封測實測值的對照基準。bot 在 `src/game/sim/progression-bot.ts`，表格由 `src/game/__tests__/progression-doc-test.ts` 產生並檢查（`UPDATE_BALANCE_DOC=1 npx jest progression-doc`）。

**玩家模型**：首次啟動在第 0 天晚上 7 點，之後依固定時刻開啟；每個操作（產出、合成、出單、賣出）2 秒；時間到或沒事可做（體力用完、也沒有可合成或可出的單）就離開。不看廣告。每一種玩家跑 20 個 seed，「第 N 天」是中位數，括號是 10%–90% 的範圍；第 0 天是安裝當天（和埋點的 `days_since_first_launch` 一致）。

**bot 比真人快**：它知道全部配方（不用等線索或阿嬤）、每一步都選有用的合成、線索單直接請走。所以表上的天數是**下限**，封測量到的真人天數會比較慢，兩者的倍數就是這次封測要校正的「真人效率」。

### 觀察（模擬，2026-11-25）

- **9,900 金幣的總量對，速度比假設快**：大約 90 張訂單就花完 9,900。GDD 假設每天 15–30 張、約 2 週（大約 210–420 張），模擬的平均每張金幣比假設高很多，因為訂單階數隨玩家等級提高，貴客單又特別值錢。即使是輕度玩家，bot 也在第 5 天走完。
- **貴客單約佔一半收入**：三種玩家都一樣，一般單 48%、貴客單 48–49%、完售獎勵 3–4%，賣出品項不到 1%。貴客單的金幣是 `vipCoinMultiplier`（×3）。換算成每點體力，大約是一般單的 3 倍，是後期加速的主因。
- **3–6 分鐘的玩法不會卡在體力**：輕度和中度玩家沒有一次是因為體力用完而離開，玩到時間就走了。開幕週上限 200、離線回復、出單退體力、完售 +10、升級 +20 加起來，體力只會卡住「一次玩很久」的重度玩家（66% 的開啟玩到體力用完，平均一次 24 分鐘）。
- **第一次升級與第一次發明都在第 0 天**：教學期間的新手訂單（×2.5）讓第一次升級很快達成。第一次發明則有阿嬤教配方 #1（`tutorialHint`），所以 bot 知道配方，真人也會被教到，這個值不算太樂觀。

**還不改數值**：bot 是下限，真人慢多少要等封測量到才知道（下面的 4 個指標）。如果封測的輕度玩家也在 1 週內走完，可以考慮的調整方向（都只改 `balance.ts`）：

1. 降低 `vipCoinMultiplier`（例如 3 → 2）：直接拉長後期，前期不受影響（貴客單要有發明菜才會出現）。
2. 提高 Lv3 升級費用：只拉長最後一段，也讓招牌菜更有份量。
3. 降低 `maxOrderItemLevel` 的成長速度：一般單的金幣成長變慢，但也會讓合成目標變短、手感變輕，要搭配試玩。

## 封測指標的算法（S7.5）

都在 PostHog 用 `env = production` 篩選。每個事件都帶 `days_since_first_launch`（安裝當天是 0）。

| 指標 | 目標 | 算法 |
|---|---|---|
| 第 1 天第一次升級率 | ≥ 80% | 第 0 天有 `app_open` 的玩家中，第 0 天有 `stall_upgraded`（`level = 2`）的比例 |
| 第 3 天首次發明率 | ≥ 50% | 第 0 天有 `app_open` 的玩家中，第 0–2 天有 `dish_invented`（`first = true`）的比例 |
| 前 3 天是否卡在體力 | 觀察 | 第 0–2 天每位玩家的 `energy_blocked` 次數，以及有 `energy_blocked` 的開啟佔所有 `app_open` 的比例（S7.5 新增事件：點產生器時體力不足） |
| 單次遊玩時間 | 3–6 分鐘 | `app_background` 的 `session_seconds` 中位數（S7.5 新增事件：從這次的 `app_open` 到進背景） |
| 走完 MVP 的天數 | 與上面的模擬表比較 | 每位玩家第 5 個 `stall_upgraded`（`level = 3`）的 `days_since_first_launch`；和模擬值的比值就是「真人效率」 |

> `app_background` 只在 App 進背景時送，App 被系統直接殺掉時會少一筆，中位數仍然可用。
