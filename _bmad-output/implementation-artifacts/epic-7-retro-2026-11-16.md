## 順利的地方

- **先量再加。** A3 先把啟動各階段的時間記下來，再加音效與埋點，而且都放在首幀之後，最後數字沒有變。這是第一次在加功能之前就有可比較的基準。
- **安全防護在需要之前就到位。** `.env.local` 一開始放錯成 Secret API Key，`app.config.ts` 與 `config.ts` 兩層 `phc_` 檢查讓它不可能被打包，也有測試保護。
- **實機回饋一樣很快變成修正。** 連續合成偶爾沒聲音，原因是同一個 player 的 `seekTo` 與 `play` 互相干擾，改成 player 輪流用並等 seek 完成。
- **依序審查又一次抓到真問題**，而且集中在測試環境模擬不到的地方（見下）。

## 卡關的地方

1. **App 進出背景的邊界情況。** 11 項審查修正中有 4 項和它有關：背景時送出 `app_open`、iOS 來電中斷後背景音樂不恢復、背景時仍播音效、節奏音被重設。jest 的 AppState 是假的，模擬不到「iOS 進背景後幾秒內計時器仍會跑」「來電只會變 inactive」這類情況。
2. **jest mock 的還原陷阱又出現。** 對本身就是 jest mock 的物件（AppState、AsyncStorage）用 `spyOn` 再 `mockRestore`，會把 mock 的實作清掉，之後的測試莫名壞掉。7.2 遇過一次，審查修正時又遇到一次。
3. **AC 和實作對不上。** 兩條 AC 的設計偏離（鑼聲、完售語音）只寫在 Dev Notes 沒改 AC；7.3 AC6（開發時不送）整條漏掉，Dev Notes 也沒提，等 Acceptance Auditor 才抓到。
4. **「測不到」被當成「不需要」。** 7.1 因為反向驗證測不到而刪掉 `stopped` 檢查，審查才發現 `seekTo` 完成後的路徑其實需要它。問題是測試沒走到那條路徑。
5. **含跳脫字元的腳本又壞了一次。** memory 已經記著不要用 heredoc 寫含 `\n` 的 Python，審查修正時仍然發生。
6. **（使用者回饋）剛進入畫面時圖片載入很慢。** 推測主因是 Expo Go 開發模式：每張圖都從開發伺服器經 tunnel 下載（圖片共約 11 MB、120 個檔），正式建置會把圖片打包在 App 裡。
   - **已確認（2026-11-16）**：用 tunnel 開啟後完全關掉再開，第二次明顯變快（圖片已存在手機上），所以慢是第一次經 tunnel 下載造成的，不是 App 本身的問題，不用改程式。LAN 模式這次無法比較：手機（192.168.0.x）和電腦（192.168.1.x）不在同一個網段。
   - 上架前用正式建置（7.6 效能驗收）再確認一次。

## 關鍵心得

- 訂閱 AppState 的服務要用同一張檢查表：iOS 背景寬限期內計時器仍會跑、`inactive` 不等於 `background`、音訊中斷由系統直接暫停、冷啟動時可能就在背景。只靠 jest 模擬不出來。
- 本身就是 jest mock 的物件，不要 `spyOn` 再 `mockRestore`；用 `jest.mocked(x).mockXxxOnce`，或每個測試前重設。
- 寫 story 時逐條把 AC 對應到 task；設計要偏離 AC 時，當下就改 AC（並請使用者確認），不要只寫在 Dev Notes。
- 反向驗證測不到某段防護時，先試著補一個走到那條路徑的測試；確定路徑真的走不到才刪。
