# 夜市合成：平衡數值

數值的唯一來源是 `src/game/content/balance.ts`。這份文件放的是由規則層函式**算出來**的參考表，讓設計、教學（S6.4）與封測校正（S7.5）有共同的基準。

## 各玩家等級每單期望金幣

由 `expectedOrderCoins(playerLevel, stalls)` 算出（S1.6），是一般訂單金幣的數學期望值，對應 `createOrder` 的抽法：

- 鏈：從已開的攤位均勻抽（FR7）
- 階數：2 到 `min(2 + ⌊玩家等級 / 2⌋, 該鏈長度)` 均勻抽
- 品項數：玩家 Lv3 起有 40% 機率兩品項
- 金幣：每個品項 `5 × baseCost × 攤位加成`，攤位每升 1 級 +10%（FR8、FR15）

兩個欄位分別是：玩家完全沒有重開攤位（只有開局的手搖飲、炸物），以及依玩家等級把能重開的攤位都重開成 Lv1（麵線 Lv3、蒸籠 Lv5、甜品 Lv7）。攤位升到 Lv2／Lv3 後，金幣會再提高 10%／20%。

## 觀察（S1.6，2026-11-09）

- **新手存到 200 金幣比預期慢**：Lv1 每單期望 10 金幣、Lv2 為 15、Lv3 為 21。手搖飲或炸物升到 Lv2 要 200 金幣，照這個數字大約要 13–15 張訂單，S6.4 要求的「8 張訂單以內」達不到。這要在 S6.4 處理，例如調整新手訂單，或降低第一次升級的費用；這裡先記錄，不改數值。
- **重開攤位不會提高每單期望金幣**：兩個欄位一直到 Lv9 都一樣，因為金幣只看品項階數，和是哪一條鏈無關。Lv10 起各鏈長度不同，才會出現差距。重開攤位的經濟價值來自：之後的升級加成（每級 +10%）、人龍變長（完售獎勵，S2.1），以及發明菜（E3）。GDD 估計的「約 2 週走完」，要把這一點納入考量。
- 實測校正留到 S7.5 的封測。

## 新手訂單（S6.4，2026-11-11）

處理上面「新手存到 200 金幣比預期慢」的問題，讓教學第 3 步（升級攤位）一定能完成。

- **調整**：教學期間（`meta.tutorialStep < 3`）建立的一般單，金幣 ×`tutorialOrderCoinMultiplier`（2.5），在建立訂單時鎖定（RC-3）。教學完成後建立的訂單恢復原價。
- **驗證**（`src/game/__tests__/tutorial-test.ts`）：
  - Lv1 的訂單都是 L2，每張 25 金幣；前 7 張一定在 Lv1 建立（做完 5 張才升 Lv2，補單晚一張），第 8 張至少 25，所以 **8 張最少 200 金幣**。
  - 用 `expectedOrderCoins` 依累計 XP 推算 8 張訂單的期望總和 ≥ 200。
  - 50 個 seed 實際交 8 張單，每一局都 ≥ 200。
- 只在玩家 Lv2 以下套用（`tutorialBonusMaxLevel`，E6 code review）：前 8 張單一定在 Lv1、Lv2 建立，保證不變；玩家一直不升級攤位、教學沒完成時，到 Lv3 也會恢復原價，不能無限期拿 ×2.5。
- 貴客單與線索單不受影響（教學期間還沒有發明菜，不會出現）。
- 實測校正一樣留到 S7.5。
