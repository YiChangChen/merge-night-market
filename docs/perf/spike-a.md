# Spike A：夜市街效能量測（第一階段：iPhone）

這份文件說明怎麼在 iPhone 上量測夜市街原型的效能，以及量完要回報哪些數字。對應 Story 1.3。

## 這一階段量得到什麼、量不到什麼

| 指標 | 第一階段（iPhone） | 第二階段（Android 中階機） |
|---|---|---|
| UI 執行緒 FPS、卡頓比例 | ✅ App 內效能面板 | Flashlight |
| JS 執行緒 FPS | ✅ App 內效能面板 | Flashlight |
| 進入夜市街的時間 | ✅ App 內效能面板（點擊到畫面首次排版） | 在 S1.7 的分頁上重量 |
| 冷啟動 | ❌ 透過 Expo Go 啟動時，會一併算到 Expo Go 本身和下載 bundle 的時間，沒有參考價值 | `adb shell am start -W` |
| 記憶體 | ❌ 沒有 Mac 就沒辦法用 Instruments | `adb shell dumpsys meminfo` |

**限制：**iPhone 比 Pixel 6a 快，而且 `--no-dev --minify` 仍在 Expo Go 裡執行，不是真正的 release build。所以第一階段的結論只是**暫定**，最晚在 S7.6 之前要用 Android 中階機複驗。

## 步驟

1. iPhone 從 App Store 安裝 **Expo Go**，並和電腦連上同一個 Wi-Fi。
2. 在專案目錄用「正式版 JS 模式」啟動，兩種連線方式擇一：

   ```bash
   # A. 同一個 Wi-Fi（較快）：Windows 防火牆要允許 Node.js 使用「私人網路」
   npx expo start --go --no-dev --minify

   # B. 網路不通時改用通道
   npx expo start --go --tunnel --no-dev --minify
   ```

   `--no-dev --minify` 會關掉開發模式的額外檢查，數字才會接近正式版。**不要用一般的 `npx expo start` 量測**，開發模式會慢很多。
3. **在 Expo Go 裡面開啟，不要用相機掃描。**相機掃到 `https://…` 網址時會用瀏覽器開，瀏覽器會向伺服器要網頁版，結果就是「Gateway Timeout」。
   - 打開 Expo Go。電腦和手機登入同一個 Expo 帳號時，專案會出現在「Development servers」底下，直接點就好。
   - 沒出現的話，點「Enter URL manually」，輸入終端機上顯示的 `exp://…` 網址。
   - 第一次載入要打包，大約 10–30 秒；用通道會更慢。如果逾時，在 Expo Go 裡重新載入一次就好。
4. 量測前的準備：
   - 關掉低耗電模式。
   - 電量 50% 以上，手機不要在充電時發燙。
   - 關掉其他背景 App。
   - 記下 iPhone 型號（設定 → 一般 → 關於本機）。
5. 在棋盤畫面右下角點粉紅色的 **Spike A** 按鈕，進入夜市街原型。
6. **FPS（量 3 次）：**
   1. 按「開始量測」。
   2. 接下來 30 秒持續用手指**左右來回捲動**夜市街。煙火每 5 秒會自動放一次。
   3. 時間到之後，面板會多出一行結果。
   4. 重複 3 次。面板最下方的黃字會顯示 3 次的中位數。
7. **進入時間（量 10 次）：**按「← 回棋盤」，再點「Spike A」進入，重複 10 次。面板會顯示「進入時間」的中位數。
8. 把面板截圖傳給我，或照下面的格式回報。

## 回報格式

```
iPhone 型號：
FPS 第 1 次：UI __ FPS・卡頓 __%・JS __ FPS
FPS 第 2 次：UI __ FPS・卡頓 __%・JS __ FPS
FPS 第 3 次：UI __ FPS・卡頓 __%・JS __ FPS
中位數：UI __ FPS・卡頓 __%・JS __ FPS
進入時間中位數（10 次）：__ ms
主觀感受：捲動是否順、煙火時有沒有頓一下
```

## 第一階段結果（2026-11-09）

| 項目 | 結果 | 門檻 | 判定 |
|---|---|---|---|
| 裝置與模式 | iPhone 16（60 Hz）、Expo Go、`--no-dev --minify` | — | — |
| UI 執行緒 | 60.1 / 60.1 / 60.1 FPS，卡頓 0.0%（中位數 60.1 FPS、0.0%） | ≥ 58 FPS、卡頓 ≤ 5% | ✅ |
| JS 執行緒 | 60.1 / 60.1 / 60.1 FPS（中位數 60.1） | ≥ 58 FPS | ✅ |
| 進入夜市街 | 中位數 72 ms（22 次） | ≤ 300 ms | ✅ |
| 冷啟動、記憶體 | 未量測 | ≤ 3,000 ms、基準 | 第二階段 |

**結論：**純 RN + Reanimated 暫定通過，不需要評估 Skia 或 Lottie。頭像上限暫定每攤 4 個。最晚在 S7.6 之前，要用 Android 中階機複驗。

## 判斷標準

- **FPS**：架構的門檻是「平均 ≥ 58 FPS，卡頓 ≤ 5%」，以 60 Hz 為準。
  - ProMotion 機種（120 Hz）的 FPS 可能接近 120，這樣也算通過。重點看**卡頓比例**：幀間隔超過 25 ms 的幀，代表連 60 Hz 的節奏都沒跟上。
- **進入時間**：≤ 300 ms。
- **判定**：純 RN 通過 → 暫定採用純 RN。沒通過 → 依序評估 Skia、Lottie、降級方案（頭像上限 10、霓虹改成靜態）。
