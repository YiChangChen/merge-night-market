# 合成夜市：設計文件

暫定名稱，上架前要確認 App Store 與商標沒有衝突。

## 定位

iOS 單機合成經營遊戲。玩家從夜市小攤起家，合成台灣小吃、完成顧客訂單、賺錢裝修攤位。

玩法類型參考 [Foodstars: Merge & Cook](https://apps.apple.com/us/app/-/id6753862216)（產生器 → 合成 → 訂單 → 裝修）。名稱、美術、文案、數值全部原創，不使用對方的任何素材，也不走它的「世界料理加主題餐廳」路線。

首版要回答的問題只有一個：**玩家玩過之後，還會不會回來？**（看 D1、D7 留存）

## 已定決策

| 項目 | 決定 | 理由 |
|---|---|---|
| 平台 | iOS 先發 | 由 Windows 開發，用 iPhone 加 Expo Go 測試，用 EAS 建置 |
| 語言 | 繁體中文（假設，待確認） | 主打台灣，文案之後再集中抽出 |
| 題材 | 台灣夜市 | 辨識度高，與參考作品有區隔 |
| 內容量 | 約 7 天 | 剛好夠量測 D7 留存，之後進入無限訂單 |
| 體力 | 上限 100，每 2 分鐘回 1 點 | 控制進度消耗；之後才加體力玩家通常反感 |
| 後端 | 不做，存檔在本機 | 首版不需要帳號與多人功能 |
| 商業模式 | 首版不變現，預留接點 | 先驗證留存，隱私揭露也較單純 |
| 數據 | 匿名事件分析 | 否則只知道玩家沒回來，不知道原因 |
| 美術 | AI 生成加人工整理 | 需確認工具條款可商用 |
| 不做 | 1v1 對戰、雲端存檔 | 需要後端，工程量大 |

## 核心規則

- **棋盤：** 7 × 8 格。
- **產生器：** 點一下花 1 體力，在最近的空格產出 1 階品項，15% 機率直接產出 2 階。棋盤滿時不扣體力。
- **拖曳：** 相同品項合成為下一階，空格則移動，其他情況交換位置。最高階不能合成，產生器不能合成也不能賣。
- **訂單：** 同時 3 張，只要求 2 階以上且已解鎖的品項。Lv.3 起有 40% 機率要求兩樣。
- **賣出：** 點選品項後可賣錢，棋盤塞滿時也不會卡死。
- **升級：** 完成訂單得經驗，升級補 20 體力，並解鎖新產生器（Lv.3、Lv.5、Lv.7）。棋盤滿時，新產生器會排隊等空位。
- **體力：** 訂單和升級的獎勵可以超過上限，但超過上限時不自然回復。裝置時間被調回時，計時會重設。

所有數值都是初始值，集中在 [src/game/content.ts](../src/game/content.ts)，**尚未經過實際遊玩驗證**，包括「約 7 天」的內容量。

## 程式架構

| 路徑 | 職責 |
|---|---|
| `src/game/content.ts` | 合成鏈、產生器、數值 |
| `src/game/engine.ts` | 純規則函式，不碰 UI、時間來源或儲存，用單元測試涵蓋 |
| `src/game/use-game.ts` | React 狀態、AsyncStorage 存讀檔、體力計時 |
| `src/components/board.tsx` | 棋盤繪製與拖曳手勢 |
| `src/app/index.tsx` | 主畫面：HUD、訂單、資訊列 |

隨機數種子存在 state 裡，所以同一份存檔的結果可重現，也不能靠重開來重抽。

## 里程碑

1. **核心玩法（目前）：** 合成、產生器、體力、訂單、存檔，以 emoji 佔位。
2. **手感驗證：** 在 iPhone 上實際玩，調整數值與拖曳手感。
3. **攤位裝修：** 金幣目前只進不出，要加上約 15 個裝修項目。這是完整循環最後缺的一塊。
4. **新手教學與事件分析：** 先確認分析工具與 Expo Go 相容再選定。
5. **正式美術：** 先定畫風，再產約 40 個品項、5 台產生器和攤位場景。
6. **上架準備：** 申請 Apple Developer 帳號、確認名稱、設定 bundle identifier、圖示與隱私揭露，走 TestFlight 後送審。
